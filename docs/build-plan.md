# Build Plan — Voicey — dual-runtime voice-agent toolchain

> Research-complete: grounded in 5 implementation-grade research reports (Pipecat, LiveKit, Twilio+tunneling, CLI/packaging, testing/architecture prior art) + the approved product spec `docs/product-spec.md`. Codex-review APPROVED after 8 rounds (gpt-5.6-sol, 2026-07-26).

## Context

This is a greenfield open-source product defined in `docs/product-spec.md` (design-complete, user-approved): **the production toolchain around Pipecat and LiveKit** — a thin typed `Agent` config + 100% native flow code per runtime (no custom DSL, no MCP), with the engine supplying guided project creation (wizard, no pre-selected recommendations, multi-select channels, working scratch path), a browser playground, three-tier simulated-caller testing, telephony adapters (Twilio/Telnyx/Vobiz certified; Plivo/SIP beta), deployment with smoke verification, and a signed results-webhook contract with a hard invariant (every call ends in exactly one terminal event, with delivery attempted until acknowledged or visibly dead-lettered). **Production mandate: not an MVP** — each phase exits at production quality for what it contains, gated by spec §17 quality gates.

This plan turns the spec into an executable build. The name was initially
deferred and finalized as **Voicey** on 2026-07-31. This repository is the
product's home, created 2026-07-26 with the spec, this plan, and the research
reference imported into `docs/`. The predecessor project's local folder was
removed at Jigyansu's request; its committed history remains on its GitHub
remote.

## Decisions already locked (from spec — do not relitigate during build)

- Runtimes: Pipecat AND LiveKit at launch, chosen per-project at `init`; parity CI-enforced.
- Conversation logic: native `pipecat-flows` / native LiveKit agent workflows. Engine touchpoint inside flow code is `results.set()` / `set_outcome()` only.
- Tools: plain typed Python functions + HTTP tools. No MCP.
- CLI: wizard-first, zero recommendations/pre-selects, every question explicit choice with neutral factual one-liners; multi-select channel question; scratch path yields a working talking agent; live key validation at paste; every command prints next step; full flag twins + `--json`.
- Telephony: adapter Protocol per spec §5.1; Twilio is the reference/first-certified carrier.
- Webhook contract per spec §6 — **amended by research to the Standard Webhooks (Svix) signature format + retry curve** (see testing/registry/webhooks findings); invariant, rotation, DLQ, and pull parity unchanged. **The product spec itself is amended in the P0 spec-sync commit so plan and spec never disagree** (pre-1.0, zero external consumers — no compatibility break).
- License Apache-2.0; Python package with extras per runtime/carrier.
- CLI interface layer (user decision 2026-07-26): **questionary + rich flowing-wizard style** — Charm-grade polish without a full-screen TUI. Bubble Tea is Go (CLI must be Python — it imports the engine); Textual full-TUI considered and declined for now (duplicates the browser playground's live view; optional `dev --tui` dashboard is a possible post-1.0 enhancement, not in scope).

## Research findings — Pipecat (LANDED; full expanded reference at `docs/research/pipecat-api-reference.md`)

**⚠ Pipecat churns fast — most online examples are stale. Target the NEW API surface; old names are deprecated aliases removed in 2.0:** `PipelineTask`→**`PipelineWorker`**, `PipelineRunner`→**`WorkerRunner`** (`pipecat.workers.runner`); transport module paths moved to per-provider (`pipecat.transports.websocket.fastapi`, `pipecat.transports.smallwebrtc.transport`); universal **`LLMContext` + `LLMContextAggregatorPair`**; service config via nested **`Service.Settings(...)`**; JS `RTVIClient`→**`PipecatClient`**; **`allow_interruptions` is GONE** — interruption/idle/mute now live on `LLMUserAggregatorParams` (`user_turn_strategies`, `user_idle_timeout`, `user_mute_strategies`).

- **Versions (P0-resolved 2026-07-26; Cloud extension re-resolved live 2026-08-23)**: pipecat-ai **1.6.0**; Flows is built into core `pipecat.flows` (do **not** install standalone `pipecat-ai-flows`); pipecat-ai-cli **1.3.0** with its separately versioned Pipecat Cloud extension `pipecatcloud==1.1.0`. **Python ≥3.11** ⇒ combined window with LiveKit (≥3.10,<3.15) = **3.11–3.14**. ## Research findings — LiveKit (LANDED, doc-verified)

**Pin `livekit-agents==1.6.7`** (Py >=3.10,<3.15) and `anthropic==0.120.0`; service plugins as extras `livekit-agents[deepgram,anthropic,cartesia,elevenlabs,openai,silero]`. **Live correction 2026-08-23:** Anthropic 1.0 requires `httpx2`, but the pinned LiveKit plugin constructs it with `httpx.AsyncClient` and fails before media connection; 0.120.0 is the empirically compatible SDK. **Installed-pin correction 2026-07-27:** `livekit.plugins.turn_detector` emits a deprecation warning in 1.6.7; use current `livekit.agents.inference.TurnDetector(version="v1-mini")` for the local model and do not install the deprecated extra. **⚠ Worker API rewritten in 1.6.x: use `AgentServer` + `@server.rtc_session(agent_name=…)` + `server.setup_fnc` (prewarm)** — the old `WorkerOptions/entrypoint/cli.run_app(WorkerOptions)` pattern is legacy. `TurnHandlingOptions` consolidates endpointing/interruption/turn-detection (old kwargs die in 2.0 — use only the new form). One process per job; `num_idle_processes` warm pool; health check `GET :8081/`; drain via SIGTERM (default 1h in `start` mode).

- **Flows (native)**: handoff = return `(NextAgent(), "msg")` from `@function_tool`; `on_enter`/`on_exit`; typed `AgentSession[MyData](userdata=…)`; `AgentTask[Result]` + `self.complete()` for subtasks. **Prebuilt: `WarmTransferTask`, `GetDtmfTask`, `Get{Name,Email,Address,DOB,PhoneNumber}Task`, `EndCallTool`, `send_dtmf_events`** — recipes should use these, not reinvent.
- **Tools**: `@function_tool` (schema from hints+docstring — same shape as our shared tools contract ✓); `ToolError` for LLM-recoverable errors; `ctx.disallow_interruptions()` for mutating calls; async tools with `ctx.with_filler(…)` = native `say_while_running`; `session.max_tool_steps` default 3.
- **SIP (all python `lkapi.sip.*`, fully scriptable)**: `create_inbound_trunk` → `create_dispatch_rule` (individual rooms `call-` prefix + `RoomAgentDispatch(agent_name, metadata)`); their `create_sip_*` aliases are deprecated in livekit-api 1.2.0. **Twilio correction verified from the current LiveKit/Twilio guides on 2026-07-27:** Twilio Elastic SIP does not support username/password authentication on traffic originating at Twilio, so its LiveKit **inbound** trunk is number-scoped without auth. Credentials belong on the LiveKit **outbound** trunk terminating at Twilio. Secure Twilio trunks require `;transport=tls` on the Twilio origination URI and TLS on the LiveKit outbound trunk; both sides allow encrypted media. Outbound = `create_sip_participant(sip_trunk_id | inline SIPOutboundConfig(hostname="<x>.pstn.twilio.com", auth)…, wait_until_answered=True)` with `SipCallError.sip_status_code` for failure mapping. **Transfer: cold = `transfer_sip_participant` (SIP REFER); warm = prebuilt `WarmTransferTask`** — confirms LiveKit path gets both modes natively. DTMF receive = room event `sip_dtmf_received`. ⚠ Self-host needs separate `livekit-sip` service — verify in P2; LiveKit Cloud has it built in.
- **Browser**: mint `api.AccessToken(...).with_grants(VideoGrants(room_join=True,…)).with_room_config(RoomConfiguration(agents=[RoomAgentDispatch(agent_name)]))` → playground endpoint returns `{server_url, participant_token}`; client = `livekit-client` (TokenSource endpoint type).
- **Observability**: per-turn `ChatMessage.metrics` (`LLMMetrics.ttft`, `TTSMetrics.ttfb`, `EOUMetrics.end_of_utterance_delay`, correlate via `speech_id`); final `ctx.make_session_report()` → `SessionReport.chat_history` = our transcript+metrics source for the results contract. `ModelUsageCollector` for usage.
- **Testing (native)**: `AgentSession.run(user_input=…)` + `result.expect.next_event().is_function_call(…)/.is_message(…).judge(llm, intent=…)` + `mock_tools(AgentClass, {...})` + `JudgeGroup` evals — **our text tier on LiveKit wraps this directly.**
- **Deploy**: `lk agent create/deploy/rollback/status/logs` + `livekit.toml`; Dockerfile rules: glibc (no Alpine), non-root, `CMD [... "start"]`, never bake LIVEKIT_* env (injected), no .env in image.

## Research findings — Twilio + tunneling (LANDED, doc-verified)

**Media streams (Pipecat path):** bidirectional = `<Connect><Stream url="wss://…">` — wss only, NO query strings (per-call data via nested `<Parameter>` → `start.customParameters`); μ-law 8k mono base64; outbound messages `media`/`mark`/`clear`; **`clear` is the barge-in primitive** (flush buffer on VAD); `mark` round-trip = playback tracking; DTMF receive works only on bidirectional streams; exactly one bidirectional stream per call; `<Connect>` blocks all subsequent TwiML until WS closes.

**⚠ Transfer design consequence (spec §5/§2 `behavior.transfer_number`):** redirecting a live call (`calls.update`) EXITS `<Connect>` and kills the media stream → on Pipecat/Twilio: **cold transfer = trivial** (`calls.update(twiml="<Dial>…")` after agent says handoff line); **warm transfer requires a conference-bridge architecture** (caller parked in conference; human dialed in; AI briefs; AI leg dropped) — schedule warm-transfer-on-Pipecat as its own P3 work item; LiveKit path gets warm transfer via native SIP REFER/prebuilt task instead. Engine API stays one `transfer()` capability with per-adapter mode flags {cold, warm}.

**Signature validation:** HMAC-SHA1 over exact public URL + alphabetically-sorted concatenated form params, base64; use `twilio.request_validator.RequestValidator`, never hand-roll. Behind tunnels MUST reconstruct public URL from `X-Forwarded-Proto`/`Host` (uvicorn `--proxy-headers`); WS upgrade validated with empty params against the `wss://` public URL; header arrives lowercase.

**Number rollback (dev --phone / deploy cutover):** snapshot `voice_url, voice_method, voice_fallback_url, status_callback(+method), voice_application_sid, trunk_sid` per PN SID before pointing; **precedence gotchas:** `VoiceApplicationSid` or `TrunkSid` set ⇒ `VoiceUrl` ignored; setting one clears the other; attaching a number to a SIP trunk clears its voice config. Restore = null what we set, rewrite saved values. Purchase = search `AvailablePhoneNumbers/{ISO2}/Local` → `POST IncomingPhoneNumbers` (can set VoiceUrl at purchase).

**Outbound:** `calls.create(To, From, Url|Twiml≈4KB, StatusCallback[events], Timeout)`; default 1 CPS (raise via business profile — document). AMD: `MachineDetection=Enable|DetectMessageEnd`, async via `AsyncAmd=true`+callback (`AnsweredBy`: human|machine_start|machine_end_*|fax|unknown); ⚠ async AMD consumes one of 4 forked-audio slots while running — sequence AMD completion vs stream start carefully; tuning params exposed but shrinkage raises `unknown` rate.

**Recording:** `Record=true` + `RecordingChannels=dual` + `RecordingStatusCallback` at create, or start-on-live via `calls(sid).recordings.create()`; pause/resume/stop via `Twilio.CURRENT`. **Media URLs require HTTP Basic auth (since 2023)** → engine downloads with creds into its own storage. **Contract (DECIDED, Codex R2/R3 — in spec-sync): `call.completed` ships immediately with a stable engine-owned recording reference (status pending); a separate non-terminal `call.recording.ready` event fires when the artifact is available; pull API resolves the reference.** DTMF send = `<Play digits>` via call update or `SendDigits` at create (no media-stream send path).

**SIP trunking for LiveKit path — fully API-automatable, zero console:** `POST trunking/v1/Trunks{DomainName:*.pstn.twilio.com}` → `OriginationUrls{SipUrl: LiveKit ingress}` → SIP CredentialList create+associate → `Trunks/{TK}/PhoneNumbers{PN}`; outbound = INVITE to trunk DomainName with credential auth. (⚠ attaching PN to trunk clears its webhook config — rollback snapshot must cover this.)

**Telnyx parity confirmed** (P2 carrier): bidirectional streaming via `stream_bidirectional_mode:"rtp"` (+broader codecs incl. PCMU/OPUS/L16), TeXML for Twilio-compatible XML, number voice-settings API, SIP trunking via FQDN/credential connections. Adapter delta = JSON Call Control model vs TwiML.

**Tunnel decision (supersedes spec's cloudflared-default):** resolution order = `NGROK_AUTHTOKEN` present → ngrok (`ngrok-python`, native WS, stable free dev-domain, optional edge Twilio sig-verify; free limits: 1 domain/3 endpoints/1GB) → else cloudflared quick tunnel (zero-account; parse URL from log output; 200 concurrent cap; no SLA; fine with uvicorn origins — the known Twilio-WS failure is specific to wrangler/miniflare origins; offer `--protocol http2` fallback; never with SSE). `voicey doctor` verifies tunnel WS round-trip before pointing a real number.
